## Deliverables

### ✅ 1. POST /api/v1/copilot/propose Endpoint

**Files Created**:
- `apps/api/app/api/v1/copilot/propose/route.ts` (328 lines)

**Features**:
- **Natural Language to Rule**: Uses GPT-4 to convert queries like "increase prices by 10%" into structured PricingRule objects
- **Automatic Simulation**: Runs impact preview before persisting
- **Persist as Disabled Draft**: Saves rule with `enabled: false` and `source: 'copilot'`
- **Create Preview Run**: Generates RuleRun in PREVIEW state with simulation data
- **Full Audit Logging**: Logs to CopilotQueryLog with prompt, rule ID, run ID, and results
- **RBAC Enforcement**: Requires EDITOR role minimum

**Request Schema**:
```typescript
{
  projectSlug: string
  query: string
  userId?: string
  metadata?: Record<string, unknown>
}
```

**Response**:
```typescript
{
  rule: {
    id: string
    name: string
    enabled: false
    selector: object
    transform: object
    source: "copilot"
  }
  previewRun: {
    id: string
    status: "PREVIEW"
  }
  simulation: {
    summary: { total, matched, wouldChange, totalDelta }
    results: []
  }
  metadata: {
    query: string
    explanation: string
    confidence: number
  }
}
```

**Example**:
```bash
POST /api/v1/copilot/propose
{
  "projectSlug": "demo",
  "query": "Increase prices by 15% for premium products"
}
```

## Technical Implementation

### Workflow

1. **User Query** → User types "Increase prices by 10%" in Copilot Drawer
2. **AI Processing** → POST `/api/v1/copilot` detects simulation intent
3. **Rule Generation** → GPT-4 converts query to PricingRule object
4. **Simulation** → Pricing Engine runs dry-run to preview impact
5. **Display Results** → UI shows matched products, revenue delta, confidence
6. **User Reviews** → User sees proposed rule details and simulation
7. **Save & Edit** → User clicks "Open in Rule Builder"
8. **Propose API** → POST `/api/v1/copilot/propose` persists rule + preview run
9. **Redirect** → User lands in Rule Builder to review/edit/enable

### Security Layers

1. **RBAC** — EDITOR role required for simulate and propose
2. **Schema Validation** — Zod schemas enforce request structure
3. **Tenant Scoping** — All queries filtered by projectId from slug
4. **SQL Sanitization** — Parameterized queries only, no dynamic SQL
5. **Constraint Enforcement** — Floor, ceiling, maxPctDelta applied during simulation
6. **Disabled by Default** — All proposed rules created with `enabled: false`
7. **Audit Logging** — All operations logged with full context
8. **Rate Limiting** — Recommended limits documented for production
